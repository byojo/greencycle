# wx.getLocation / wx.chooseLocation 接口权限申请说明

> 用于在微信公众平台申请 `wx.getLocation` 和 `wx.chooseLocation` 接口权限。
> 路径：微信公众平台 → 开发管理 → 接口设置 → 接口权限申请

---

## ⚠️ 审核不通过的常见根因（先排查这两项）

材料写得好不好通常不是被拒主因，**这两步没做才会一直被驳回 / 运行时报「接口无权限」**：

1. **公众平台《小程序隐私保护指引》后台未勾选"位置信息"**
   路径：公众平台 → 设置 → 服务内容声明 → 用户隐私保护 → 在"收集你使用小程序的必要信息"中勾选"位置信息"，并填写用途说明，提交审核。**这一步不在代码里，必须在后台操作。**

2. **小程序代码未实现隐私授权弹窗**
   微信 2023-08-30 起硬性要求：调用 `wx.getLocation` / `wx.chooseLocation` 前，必须先弹《小程序隐私保护指引》让用户点同意。
   本项目已在 `miniprogram/utils/privacy.js` 封装 `requirePrivacy()`，并在 `home.js`、`rider-orders.js` 调用定位前接入，**符合合规要求**。

只要后台隐私指引声明了位置信息 + 代码有隐私弹窗，再配合下方场景说明，审核通过率很高。

## 二、需要申请的接口

### 1. `wx.getLocation`（被动获取精确 GPS 坐标）

#### 场景一：首页自动定位当前城市（用户端 · 必需）

- **使用页面：** `pages/home/home`（小程序首页）
- **代码位置：** `home.js` `loadLocation()` 调用 `wx.getLocation`
- **业务必要性：** 用户打开首页时，通过 `wx.getLocation` 获取当前经纬度，经腾讯地图逆地理编码解析出用户所在城市，在首页顶部展示。该城市用于**判断回收服务是否覆盖用户所在区域**（不同城市服务范围不同），是用户下单前的必要前置判断，无法用 IP 粗定位替代（IP 定位在城市边界、新城区等场景误差大，会导致服务范围误判）。
- **调用频率：** 每次进入首页自动调用一次（已做"手动选位后不再自动覆盖"的锁 `locationLocked`，不会频繁重复调用）
- **用户感知：** 首页顶部显示"📍 上海"等城市名称

#### 场景二：回收专员实时位置上报（专员端 · 强必要）

- **使用页面：** `pages/rider-orders/rider-orders`（回收专员工单页面）
- **代码位置：** `rider-orders.js` `reportLocation()` 调用 `wx.getLocation`
- **业务必要性：** 回收专员在工单页面在线时，通过 `wx.getLocation` 上报实时 GPS 坐标到后端。管理员派单时，系统根据专员实时位置与用户下单地址计算 Haversine 距离，**推荐距离最近的在线专员上门回收**。这是本小程序"就近派单、提升上门速度"核心调度能力的唯一数据来源，属于业务强必要场景。
- **调用频率：** 仅当专员处于工单页面且在线时，每 30 秒上报一次；离开页面即停止（`onHide`/`onUnload` 清除定时器）
- **用户感知：** 专员端无直接感知；管理员派单页显示"距离 1.2 公里 / 在线"

### 2. `wx.chooseLocation`（主动打开地图让用户选点）

#### 场景三：用户选择 / 修正位置与收货地址

- **使用页面：** `pages/home/home`、`pages/address-edit/address-edit`
- **代码位置：** `home.js` `onLocationTap()`、`address-edit.js` `onChooseLocation()`
- **业务说明：** 用户点击首页位置栏或编辑收货地址时，调用 `wx.chooseLocation` 打开微信地图，用户自主选择/修正精确位置，系统获取经纬度与地址描述，用于首页城市展示、回收订单上门取件地址、积分兑换商品配送地址。
- **调用频率：** 用户手动点击触发，每次点击一次
- **用户感知：** 打开微信地图选点界面，选择后自动填充

## 三、接口使用流程说明

```
用户打开小程序
    ↓
★ 首页自动获取城市 (wx.getLocation) → 判断服务是否覆盖该城市
    ↓
★ 用户点击位置栏 → 地图选点修正 (wx.chooseLocation) → 确认所在位置
    ↓
选择品类 → 拍照 → 填写订单
    ↓
★ 选择/编辑地址 (wx.chooseLocation) → 获取精确经纬度用于上门导航
    ↓
提交订单 → 管理员派单
    ↓
★ 回收专员上报位置 (wx.getLocation) → 系统推荐最近专员上门
    ↓
专员上门取件 → 完成回收 → 用户获积分 → 积分兑换商品配送
```

| 数据 | 存储位置 | 用途 | 分享第三方 |
|------|----------|------|-----------|
| 用户城市名 | 用户表 city | 首页展示、服务区域判断 | 否 |
| 用户地址经纬度 | 地址表 lat/lng | 回收专员上门导航 | 否 |
| 专员实时 GPS | 专员表 lat/lng | 就近派单匹配 | 否（仅管理员可见距离） |

## 四、隐私合规说明（审核必查）

1. `app.json` 已声明 `requiredPrivateInfos: ["getLocation", "chooseLocation"]`
2. `app.json` 的 `permission.scope.userLocation.desc` 已填写（26 字，合规）："用于首页城市定位、取件地址选择和回收专员就近派单匹配"
3. **代码已落地隐私授权弹窗**：`utils/privacy.js` 封装 `requirePrivacy()`，在 `home.js` 的 `loadLocation`/`onLocationTap` 和 `rider-orders.js` 的 `reportLocation` 调用定位接口前先调用 `wx.requirePrivacyAuthorize()`，用户同意后才继续。**满足微信 2023-08-30 隐私新规。**
4. 用户首次使用定位时弹出隐私授权框，可自主选择同意或拒绝；拒绝后业务降级（首页显示"点击定位"、专员停止上报），不再反复骚扰
5. 用户可在「设置」随时撤销位置授权
6. 定位数据仅用于回收业务，不分享任何第三方
7. **需在公众平台后台《隐私保护指引》中勾选"位置信息"用途并提审**（见文首说明）

## 五、申请填写模板（复制到微信平台）

### wx.getLocation 申请理由：

```
叮当回收是一款旧物上门回收小程序。wx.getLocation 用于两个业务必要场景：

1. 首页自动定位城市：用户进入首页时获取当前经纬度，解析城市用于判断回收服务是否覆盖该区域（不同城市服务范围不同，是下单前必要前置判断，IP 粗定位在城市边界误差大无法替代）。每次进入调用一次。

2. 回收专员实时位置上报：专员在工单页在线时每30秒上报GPS坐标，管理员派单时按距离推荐最近的在线专员上门回收，是本小程序就近派单核心能力的唯一数据来源。离开页面即停止上报。

合规方面：app.json 已声明 requiredPrivateInfos，且调用前已接入 wx.requirePrivacyAuthorize 隐私授权弹窗，用户同意后才获取位置；定位数据仅用于回收业务，不分享第三方，用户可随时撤销授权。
```

### wx.chooseLocation 申请理由：

```
叮当回收是一款旧物上门回收小程序。wx.chooseLocation 用于用户主动选点：

1. 首页位置栏点击：用户主动点击调起地图选点，确认/修正所在位置，保证服务区域判断准确。
2. 收货/取件地址选择：用户新增或编辑地址时调起地图选点，获取精确经纬度，用于回收专员上门导航与积分兑换商品配送。

均由用户手动点击触发，每次一次；定位数据仅用于回收业务，不分享第三方。
```

## 六、注意事项

1. **后台隐私指引必须勾选"位置信息"**：这是审核通过 + 运行不报「接口无权限」的前置条件，仅改代码不够
2. **服务类目**：确保已添加"环保回收"或"生活服务"类目
3. **代码一致性**：提交审核的代码须与申请描述一致，审核团队可能核对 getLocation/chooseLocation 调用位置
4. **腾讯地图 Key**：逆地理编码用的 Key 需在腾讯地图控制台启用 WebServiceAPI
