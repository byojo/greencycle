## 二、需要申请的接口

### 1. `wx.getLocation`

**使用场景：**

#### 场景一：首页城市定位（用户端）

- **使用页面：** `pages/home/home`（小程序首页）
- **使用代码位置：** `home.js` 第 61-134 行，`loadLocation` 方法（自动定位）、`onLocationTap` 方法（点击调起地图）
- **业务说明：** 用户打开小程序首页时，通过 `wx.getLocation` 获取用户当前经纬度坐标，再调用腾讯地图逆地理编码 API 解析出用户所在城市名称，在首页顶部展示用户当前所在城市，帮助用户确认回收服务是否覆盖其所在区域。当用户**点击首页顶部的位置栏**时，调用 `wx.chooseLocation` 调起微信地图选点界面——首次会弹出 `scope.userLocation` 授权确认弹窗，用户确认授权后可在地图上选择/修正自己的位置，系统再用选点坐标反查城市名并更新首页展示。
- **调用频率：** `wx.getLocation` 每次进入首页自动调用一次；`wx.chooseLocation` 由用户手动点击触发，每次点击调用一次
- **用户感知：** 首页顶部显示"📍 上海"等城市名称；点击位置栏会弹出微信授权确认框并打开地图选点
- **是否展示给用户：** 是，城市名称直接展示在首页顶部，授权与地图选点均为用户主动触发

#### 场景二：回收专员实时位置上报（专员端）

- **使用页面：** `pages/rider-orders/rider-orders`（回收专员工单页面）
- **使用代码位置：** `rider-orders.js` 第 52-58 行 `reportLocation` 方法
- **业务说明：** 回收专员在工单页面时，通过 `wx.getLocation` 每 30 秒上报一次实时 GPS 坐标到后端服务器。管理员在派单时，系统根据回收专员的实时位置与用户下单地址计算 Haversine 距离，推荐距离最近的在线专员进行上门回收，提升派单效率和上门速度。
- **调用频率：** 每 30 秒自动调用一次（专员在工单页面时）
- **用户感知：** 专员端无直接感知，管理员派单页面显示"距离 1.2公里 / 在线"等信息
- **是否展示给用户：** 管理员在派单时可见专员距离和在线状态

### 2. `wx.chooseLocation`

**使用场景：**

#### 场景三：用户选择收货/取件地址

- **使用页面：** `pages/address-edit/address-edit`（地址编辑页面）
- **使用代码位置：** `address-edit.js` 第 113-130 行 `onChooseLocation` 方法
- **业务说明：** 用户在新增或编辑收货地址时，点击"选择位置"按钮调用 `wx.chooseLocation` 打开微信地图选点界面，用户在地图上选择精确位置后，系统获取经纬度坐标和地址描述，自动填充到地址表单中。该地址用于：1)回收订单的上门取件地址；2)积分兑换商品的配送地址。准确的经纬度坐标确保回收专员能导航到用户指定位置上门回收。
- **调用频率：** 用户手动点击触发，每次点击调用一次
- **用户感知：** 打开微信内置地图选点界面，选择后自动填充地址
- **是否展示给用户：** 是，选中的地址直接显示在地址表单中

## 三、接口使用流程说明

### 回收订单完整流程（涉及定位的环节标注 ★）

```
用户打开小程序
    ↓
★ 首页自动获取城市定位 (wx.getLocation) → 展示当前城市
    ↓
★ 用户点击首页位置栏 → 调起地图 (wx.chooseLocation) → 授权确认+选点修正位置
    ↓
用户选择回收品类 → 拍照上传 → 填写订单信息
    ↓
★ 选择/编辑收货地址 (wx.chooseLocation) → 获取精确经纬度
    ↓
提交回收订单（保存取件地址+经纬度）
    ↓
管理员派单
    ↓
★ 回收专员上报位置 (wx.getLocation) → 系统推荐最近专员
    ↓
回收专员上门取件 → 完成回收 → 用户获得积分
    ↓
用户积分兑换商品（配送到收货地址）
```

### 定位数据存储与使用说明

| 数据 | 存储位置 | 用途 | 是否分享给第三方 |
|------|----------|------|------------------|
| 用户城市名 | 用户表 city 字段 | 首页展示、服务区域判断 | 否 |
| 用户收货地址经纬度 | 地址表 lat/lng 字段 | 回收专员上门导航 | 否 |
| 专员实时GPS坐标 | 专员表 lat/lng/last_location_at | 就近派单匹配 | 否（仅管理员可见距离） |

## 四、隐私合规说明

1. 小程序已在 `app.json` 中声明 `requiredPrivateInfos: ["getLocation", "chooseLocation"]`
2. 小程序已在 `app.json` 的 `permission.scope.userLocation` 中填写了位置用途说明（限制 30 字以内，当前为："用于首页城市定位、取件地址选择和回收专员就近派单匹配"）
3. 用户首次使用定位功能时，系统会弹出微信授权弹窗，用户可自主选择授权或拒绝
4. 用户可在「设置」页面随时撤销位置授权
5. 定位数据仅用于回收业务，不用于其他用途，不分享给任何第三方
6. 小程序已配置隐私政策页面，明确告知用户位置信息的收集和使用方式

## 五、申请填写模板（复制到微信平台）

### wx.getLocation 申请理由：

```
叮当回收是一款旧物上门回收小程序。本小程序使用 wx.getLocation 接口用于以下两个核心业务场景：

1. 首页城市定位：用户打开小程序首页时，通过 getLocation 获取用户当前经纬度，调用腾讯地图逆地理编码解析城市名称，在首页展示用户所在城市，帮助用户确认回收服务覆盖区域。调用频率：每次进入首页调用一次。

2. 回收专员位置上报：回收专员在工单页面时，通过 getLocation 每30秒上报实时GPS坐标。管理员派单时，系统根据专员实时位置与用户下单地址计算距离，推荐最近的在线专员上门回收，提升派单效率和上门速度。调用频率：专员在工单页面时每30秒自动调用一次。

定位数据仅用于回收业务，不分享给第三方，用户可随时撤销授权。
```

### wx.chooseLocation 申请理由：

```
叮当回收是一款旧物上门回收小程序。本小程序使用 wx.chooseLocation 接口用于以下两个业务场景：

1. 首页位置修正：用户点击首页顶部的位置栏时，调用 chooseLocation 调起微信地图选点界面，首次会弹出位置授权确认框，用户确认授权后在地图上选择/修正所在位置，系统再反查城市名更新首页展示。该交互用于让用户自主确认定位城市，确保服务区域判断准确。

2. 收货/取件地址选择：用户在新增或编辑收货地址时，点击"选择位置"按钮调用 chooseLocation 打开微信地图选点界面，在地图上选择精确位置后获取经纬度坐标和地址描述，自动填充到地址表单。该地址用于：1）回收订单的上门取件地址，确保回收专员能准确导航到用户位置；2）积分兑换商品的配送地址。

调用频率：均由用户手动点击触发，每次点击调用一次。定位数据仅用于回收业务，不分享给第三方。
```

## 六、注意事项

1. **腾讯地图 Key 配置：** 首页逆地理编码使用的腾讯地图 Key 需在腾讯地图控制台启用 WebServiceAPI 功能，否则定位会返回错误
2. **隐私政策：** 提交审核前需在小程序管理后台配置隐私政策，明确说明位置信息收集和使用方式
3. **服务类目：** 确保小程序已添加"环保回收"或"生活服务"相关类目
4. **代码一致性：** 确保提交审核的代码与申请描述一致，微信审核团队可能会检查代码中 getLocation/chooseLocation 的调用位置
